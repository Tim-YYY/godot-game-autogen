# 游戏美术资产需求指南

## 核心问题：要不要生图 AI？

**大多数情况下，要。** 程序化工具只能覆盖一小部分，生图 AI 覆盖不了的那部分才是"精美"的关键。

### 程序化 vs 生图 AI 覆盖矩阵

| 资产类型 | 程序化工具能否覆盖 | 生图 AI 是否必需 | 说明 |
|----------|-------------------|-----------------|------|
| 地形高度/噪声纹理 | ✅ FastNoiseLite / Material Maker | ❌ | 完全可程序化 |
| 无缝材质（岩石/木板/金属） | ✅ Material Maker | ⭕ 可选 | 程序化更快更可控，生图可做风格化 |
| 角色/怪物立绘与精灵 | ❌ | ✅ **必需** | 手绘感只能靠生图 |
| 道具/装备/图标 | ❌ | ✅ **必需** | 生图批量生成 |
| UI（按钮/面板/图标） | ⭕ 部分（纯形状） | ✅ 推荐 | 生图出风格化 UI 更精美 |
| 背景/场景美术 | ⭕ 3D 可搭场景 | ✅ 2D 必需 | 2D 背景只能生图 |
| 标题/Logo/宣传图 | ❌ | ✅ **必需** | 生图或文字转图 |
| 粒子贴图（火/烟/光晕） | ✅ 可程序化 | ⭕ 可选 | 生图可出更炫的 |

> 结论：**要做出"精美"的游戏，生图 AI 是刚需**，尤其 2D 游戏。3D 游戏的地形/材质可程序化，但角色、UI、图标仍需生图。

## 2D 游戏标准资产清单

```
game_assets/
├── gdd.md                    # 游戏设计文档
├── style_base/               # 风格基准图（先定这 3~5 张）
│   ├── hero.png              # 主角基准
│   ├── enemy.png             # 敌人基准
│   ├── scene_bg.png          # 场景基准
│   └── ui_palette.png        # UI 配色基准
├── sprites/                  # 角色/物件精灵（透明背景 PNG）
├── tilesets/                 # 瓦片集（可选，平台跳跃用）
├── bg/                       # 背景层（视差背景）
├── ui/                       # 按钮、面板、图标、血条
├── fx/                       # 特效帧（爆炸、粒子、光效）
└── audio/                    # 音效/音乐（可选，生图 API 不覆盖）
```

## 3D 游戏标准资产清单

```
game_assets/
├── gdd.md
├── style_base/               # 概念图 + 材质风格基准
├── models/                   # 3D 模型（生图 API 不产出模型，需另用 3D 生成工具或免费模型库）
├── textures/                 # 贴图（albedo/normal/roughness）
├── materials/                # 程序化材质（Material Maker / 内置 Shader）
├── ui/                       # UI 同上
└── skybox/                   # 天空盒（可生图全景）
```

> 3D 注意：生图 API 只出 2D 图，**不能直接出 3D 模型**。3D 模型需用"文生 3D"能力或免费模型库（如 KayKit、Quaternius、Poly Pizza），贴图则可用生图 API 出。

## 风格统一技巧（关键）

1. **先定风格基准**：生 3~5 张基准图，确认后把它们的共性提炼成一段**固定风格前缀**，例如：
   `flat vector art, vibrant palette, clean outlines, cute proportions, soft shadows, no text`
2. **所有后续生图复用同一前缀** + 各资产的具体描述，避免"一张写实一张卡通"的大杂烩。
3. **固定画幅与分辨率**：精灵统一 512×512 或 1024×1024，背景统一 1920×1080，减少导入后的缩放错位。
4. **透明背景**：精灵/图标/道具一律要透明背景 PNG（生图后需抠图或让模型输出带 alpha）。
5. **一致性微调**：同一角色多姿态/多表情时，把基准图作为参考图回填给生图 API（图生图），保持角色一致。

## 音频与其它

生图 API 不覆盖音频、音乐、3D 模型。需要时：音频用音效库/生成式音频工具；3D 模型用文生 3D 或免费 CC0 模型库。在 GDD 里标注这些资产的来源，避免遗漏。

## 免费素材库清单（生图 AI 的互补，尤其补 3D 模型）

生图 AI 出不了 3D 模型，也覆盖不了音频；免费素材库正好补上这两块，还能当"占位美术"快速起 Demo。

### 授权速查（下任何东西前先看）

| 授权 | 含义 | 能否商用 | 要署名吗 |
|------|------|---------|---------|
| CC0 | 公有领域 | ✅ | 否 |
| CC-BY | 需署名 | ✅ | 是 |
| CC-BY-SA | 需署名 + 相同方式共享 | ⚠️ 慎用（有传染性） | 是 |
| CC-BY-NC | 禁止商用 | ❌ 别用 | — |

### CC0 直接可商用（免署名，首选）

| 站 | 内容 | 格式 |
|----|------|------|
| Kenney（kenney.nl） | 2D 精灵/瓦片/UI/3D/音效，成套风格统一 | PNG/WAV/GLB/OBJ/FBX |
| Quaternius（quaternius.com） | 低多边形 3D 角色/怪物/场景，多数带动画 | GLTF/GLB/FBX |
| KayKit（kaylousberg.com） | 低多边形 3D kit（地牢/角色/道具 Bits） | GLB/FBX |
| Poly Haven（polyhaven.com） | PBR 材质 + HDRI + 3D 扫描 | EXR/HDR/GLB |
| ambientCG | PBR 贴图（albedo/normal/roughness）+ HDRI | PNG/EXR |

### 混合授权（逐项确认）

| 站 | 说明 |
|----|------|
| OpenGameArt（opengameart.org） | 像素风最丰富；CC0/CC-BY/OGA-BY 混用，逐文件看标签 |
| itch.io 免费素材区 | 独立作者，质量参差，授权逐包确认 |
| Poly Pizza（poly.pizza） | 1 万+低多边形模型；CC0/CC-BY 混用 |
| Sketchfab | 用 Creative Commons filter 筛选；体积大，逐个看 |

### 专项资源

| 用途 | 站 | 授权 |
|------|----|------|
| 游戏图标（UI/技能/道具） | Game-Icons.net | CC BY 3.0（要署名） |
| 角色自动绑骨 + 动画 | Mixamo（Adobe 账号） | 免费商用 |
| 像素画调色板 | Lospec | 免费 |
| 音效 | freesound.org、bfxr、Sonniss GDC 免费包 | CC0/CC-BY |

### 关键坑（实战）

1. **Quaternius / Mixamo 特殊条款**：允许商用游戏内使用，但**禁止把素材文件本身再打包分发**（不能拿去转卖）。
2. **CC-BY-SA 有传染性**：下游也得用 SA 授权，商用时尽量避开。
3. **每个素材下载时记一行**：来源站 + 作者 + 授权，存进项目 `credits.md`，出包前对一遍。
4. **混合来源易风格打架**：选一个主包当锚点，只加视觉上搭得上的资产；像素画注意"格子大小"一致（32×32 配 32×32）。

### 与生图 AI 的分工（结论）

- **生图 AI**：2D 角色/道具/图标/背景/UI——风格由你定制，是"精美"的来源。
- **免费素材库**：3D 模型、PBR 贴图、HDRI、音效、通用 UI 图标——生图出不了或没必要生成的。
- **理想组合**：生图 AI 定 2D 风格 + CC0 素材库补 3D/贴图/音频，二者并用才是完整的美术管线。
